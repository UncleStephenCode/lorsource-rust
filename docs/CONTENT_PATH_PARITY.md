# Совместимость типов материалов и URL

Источник истины: `AddTopicController`, `EditTopicController`,
`VoteController`, `TopicController`, `TopicListController` и `Section.scala`
из актуального `lorsource-java`.

## Канонические идентификаторы секций

| Тип | section id | URL-префикс | Возможности формы |
|---|---:|---|---|
| Новости | 1 | `/news/` | ссылки; изображения при `imageallowed` и наличии прав |
| Форум | 2 | `/forum/` | базовая тема, без полей опроса |
| Галерея | 3 | `/gallery/` | обязательное основное изображение и до трёх дополнительных |
| Опросы | 5 | `/polls/` | 15 вариантов и `multiSelect` |
| Статьи | 6 | `/articles/` | премодерация; изображения при `imageallowed` и наличии прав |

Старый Rust seed ошибочно назначал статьям id 4. Миграция
`0018_content_type_parity.sql` переносит такую секцию и её группы на Java-id 6
без изменения id тем.

## Создание и редактирование

| Операция | Метод и path | Совместимый контракт |
|---|---|---|
| Выбор типа | `GET /add-section.jsp` | необязательные `tag`; ссылки на Java section id |
| Выбор группы | `GET /add-section.jsp?section=ID` | при единственной доступной группе redirect на `/add.jsp?group=ID` |
| Форма | `GET /add.jsp?group=ID` | группа фиксирована hidden-полем; поля зависят от свойств секции |
| Создание | `POST /add.jsp` | urlencoded либо multipart, preview/draft, poll и изображения в одном запросе |
| Редактирование | `GET /edit.jsp?msgid=ID` | Java-параметр `msgid`; группа не редактируется |
| Сохранение | `POST /edit.jsp` | `msgid`, `poll[variantId]`, `newPoll[index]`, `multiselect`; multipart для изображений |
| Голосование | `POST /vote.jsp` | `voteid` и повторяемый `vote`; одна транзакция для пользователя и счётчиков |

При создании опрос использует `poll[0]` … `poll[14]` и `multiSelect` с
заглавной `S`. Старые плоские Rust-поля временно принимаются сервером, но не
генерируются. Не существовавший в Java `/addphoto-topic.jsp` удалён: галерея
создаётся только с изображением в исходном multipart `/add.jsp`.

Изображения совместимы в обе стороны на уровне схемы и файлов. Java-поля
`extension`/`main` и ранние Rust-поля
`original`/`medium`/`thumbnail`/`primary_image` синхронизируются миграцией.
Новые файлы сохраняются в канонические
`/images/{id}/{original.ext|500px.jpg|1000px.jpg|1500px.jpg|2000px.jpg}`;
для существующих Java-записей пути и реальные размеры восстанавливаются при
чтении. Одиночное изображение и набор изображений используют DOM оригинальных
`image.tag` и `imageslider.tag`.

## Отображение

Канонический материал открывается по
`/{news|forum|gallery|polls|articles}/{group}/{id}`. Страницы комментариев —
`.../page{page}`, ветка — `.../thread/{threadRoot}`. Неверные section/group в
URL перенаправляются на канонический URL темы.

Для опроса сохранены ветви оригинального JSP:

- неподтверждённый опрос показывает блокировку и выключенные варианты;
- до голосования показывается форма и ссылка `?results=true`;
- анонимному посетителю показываются вход и регистрация;
- после голосования, по `?results=true` или после завершения показываются
  результаты, сортировка по числу голосов, выбор пользователя, проценты,
  прогресс и число проголосовавших при мультивыборе.

Актуальный декларативный аудит Spring/Axum генерируется в
`docs/generated/route_coverage.json`; фиксированное число route здесь не
дублируется. Этот аудит проверяет method/path, но не доказывает
совпадение параметров, DOM, прав и побочных эффектов. Динамические topic
paths дополнительно проверяют формат `pageN` в обработчике и возвращают 404
для лишних форм.
